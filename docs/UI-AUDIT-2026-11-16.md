# Аудит интерфейса NABS — 16.11.2026

Ветка: существующая `dev`, tracking `origin/dev`; коммит `575347b`.
Стенд: Windows, Python 3.12, PostgreSQL 17.11, Edge/Playwright.

Подтверждены 8 проблем. UI-исправления пока не внесены.
После устранения блокеров развёртывания все 12 страниц ответили HTTP 200 без
JavaScript-ошибок при загрузке: Devices, Dashboard, Users, User Groups, Device Groups,
Credentials, Drivers, Search, Reports, Scheduler, Validation Profiles, Logs.
Это проверка загрузки страниц, а не всех действий на каждой странице.

В сценарии одиночной проверки ответ `/device_status/` подменён в браузере,
а конфиги созданы в настоящей локальной БД. Оборудование не опрашивалось.
Загрузка файла, чтение версий и отправка формы выполнялись через настоящий сервер.
Временные устройства 192.0.2.1/2 и связанные данные после проверки удалены.

## 1. P2 — просмотр и сравнение не включаются после одиночной проверки

Шаги: открыть список с устройством без конфигов; получить первый конфиг через
Check now; затем получить вторую отличающуюся версию без обновления страницы.
Факт: статус зелёный, время новое, View Config остаётся disabled; после второй
версии Compare также disabled. Обычная перезагрузка страницы восстанавливает
состояние, рестарт сервиса не требуется.

Причина: `app/templates/devices.html:379`, обработчик `.done` на строке 462
обновляет статус, даты, vendor и validation, но не ссылки действий.
`app/views/device_status.py` не возвращает явные has_config/can_compare.
Старый checkDevice1 содержит другую логику, но кнопка вызывает checkDevice.

Исправление: общий обработчик строки для проверки и загрузки файла; API возвращает
наличие конфига и предыдущих версий. Приёмка: первый конфиг включает просмотр,
второй — сравнение; ошибка опроса не отключает доступ к уже сохранённым конфигам.

## 2. P2 — поиск и сортировка таблицы используют устаревшие значения

Шаги: Check now возвращает нового производителя; поиск по его названию.
Факт: виден AuditVendorNew, но поиск DataTables возвращает 0 строк.
После перехода из ошибки в Ok атрибут data-order статуса остаётся равным 2.

Причина: `app/templates/devices.html:397,470,497` обновляет DOM напрямую;
кэш DataTables и ключи сортировки не обновляются. Аналогичный риск для дат/валидации.
Исправление: обновлять через API таблицы либо инвалидировать строку после
синхронизации DOM и data-order, сохраняя страницу и фильтр.
Приёмка: поиск и сортировка сразу учитывают новые значения.

## 3. P1 — диалог другого устройства может сохранить изменения в предыдущем

Шаги: открыть Edit устройства A, закрыть; открыть Edit устройства B при сбое
загрузки `/device_settings/`.
Факт: остаются поля A, edit_device_btn.value указывает на A, Save активна.
В проверке запрошен ID 8, целевой ID остался 7. Сохранение не нажималось.

Причина: `app/templates/devices.html:650` открывает общий диалог до ответа,
не очищает ID/поля и не блокирует Save/Delete. `.fail(handleError)` лишь сообщает
об ошибке. Нет защиты от запоздавшего ответа при переключении устройств.
Исправление: очистка и блокировка действий до успешной загрузки, отмена прежнего
запроса или сверка ID, сохранение блокировки при ошибке.
Приёмка: сбой/медленный ответ не позволяют изменить A при открытии B.
Похожая схема есть в Credentials/Drivers, отдельно там ещё не воспроизводилась.

## 4. P2 — копирование исчезает после выбора другой версии

Шаги: открыть конфиг и выбрать другую дату.
Факт: количество #copyConfigBtn меняется с 1 на 0.
Причина: `app/templates/config_page.html:133` пересоздаёт таблицу без кнопки,
которая есть в исходной серверной разметке.
Исправление: вынести кнопку из заменяемого блока или сохранять её при рендере.
Приёмка: копирование доступно после каждого переключения и копирует выбранную версию.

## 5. P2 — обычный ввод в поиске конфига вызывает JS-ошибку

Шаги: ввести `[` в Search in config.
Факт: SyntaxError: Invalid regular expression: /[/i: Unterminated character class.
Причина: `app/templates/config_page.html:172` передаёт ввод в new RegExp без
экранирования/обработки ошибок, хотя интерфейс не обозначает поиск как regex.
Исправление: поиск обычной строки по textContent; regex — отдельный явный режим
с проверкой корректности. Приёмка: `[`, `(` и обратная косая черта не ломают поиск.

## 6. P2 — неизменённый файл ложно делает статус устройства зелёным

Шаги: есть конфиг и статус SSH timeout; загрузить тот же файл.
Факт: API возвращает success/no_changes, UI показывает Ok. После обновления
страницы снова SSH timeout.
Причина: `app/templates/devices.html:898` делает любой успешный upload зелёным;
`app/modules/upload_config.py:199` при совпадении не меняет статус в БД.
Загрузка файла сама по себе не подтверждает доступность оборудования по SSH.
Исправление: отделить результат загрузки от статуса соединения, обновлять строку
фактическими данными сервера. Приёмка: одинаковый файл не превращает ошибку SSH в Ok.

## 7. P1 — разные конфиги одной минуты нельзя надёжно выбрать

Шаги: сохранить две разные версии в одну минуту.
Факт: у двух option одинаковое значение 2026-11-16 10:02. В тесте последняя
страница показывает вторую версию вместо третьей сохранённой.
Причина: время хранится строкой с точностью до минуты и используется как ID версии.
`app/modules/dbutils/db_utils.py:158,197,215` сортирует только по timestamp и
берёт first(); список устройств использует id DESC. Экраны расходятся в том,
какая версия последняя.
Исправление: выбирать по уникальному config_id с проверкой принадлежности
устройству; единый порядок timestamp+id либо id, более точное отображение времени.
Приёмка: обе версии доступны; просмотр, сравнение, копирование и удаление
однозначно используют выбранный ID.

## 8. P2 — добавление без доступного Credentials завершается HTTP 500

Шаги: есть группа устройств, но нет доступных пользователю профилей Credentials;
заполнить остальные поля Add Device, нажать Add.
Факт: в select 0 вариантов, form.checkValidity() возвращает true, отправка даёт 500.
Причина: `app/templates/devices.html:148` не требует Credentials и не объясняет
пустой список; `app/views/devices.py:91` вызывает int(None) до валидации.
Исправление: понятное пустое состояние со ссылкой на создание профиля, блокировка
формы до выбора; серверная валидация с сообщением вместо 500.
Приёмка: первый запуск объясняет порядок настройки и не приводит к 500.
